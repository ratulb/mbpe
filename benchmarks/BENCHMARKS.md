# Benchmarks

## What we benchmark

Three BPE operations across four implementations:

| Operation | What it measures |
|-----------|-----------------|
| **train** | Time to build the merge vocabulary from a corpus (Mojo only; Python/Rust use pre-built encodings) |
| **encode** | Tokenise a text into integer IDs |
| **decode** | Convert integer IDs back to text |

### Implementations

| Label | Language | What |
|-------|----------|------|
| `mojo` | Mojo | Our `BPETokenizer` — 2 pre-tokeniser variants (gpt2, gpt4) × 4 vocab sizes (500, 1000, 2000, 4000) |
| `tiktoken_py` | Python | OpenAI's `tiktoken` library — `gpt2` + `cl100k_base` encodings |
| `mbpe_py` | Python | Our Mojo library exposed via Python bindings — `gpt2`, `cl100k`, `o200k` encodings (pre-loaded from `.tiktoken` files) |
| `tiktoken_rs` | Rust | `tiktoken-rs` crate — `p50k_base` (GPT-2) + `cl100k_base` (GPT-4) |

## Methodology

### Timing

- **train**: single run (full wall-clock)
- **encode**: best of 20 iterations (first encode excluded — it includes one-time setup like regex compilation)
- **decode**: best of 20 iterations
- All times in milliseconds, throughput in million tokens / second (Mtok/s)

### Corpus sizes

Six corpora generated from the base `benchmarks/corpus.txt` (~1 MB): 10 KB, 100 KB, 500 KB, 1 MB, 2 MB, 5 MB. Generated by `generate_corpora.py`.

### Vocab sizes (Mojo only)

Each Mojo variant is benchmarked at 4 target vocab sizes: 500, 1000, 2000, 4000 (the actual size may be slightly lower if the corpus doesn't support enough merges).

## Markdown report

Both `run.sh` and `quick_bench.sh` produce a complete markdown report on stdout. The report structure:

1. **Hardware environment** — CPU, cores, RAM, OS, tool versions
2. **Executive summary** — headline numbers: train time, encode/decode throughput, speedup ratios
3. **Combined comparison table** — all 4 implementations in one table, grouped by encoding, with MB/s alongside M tok/s for fair cross-encoding comparison
4. **Native Mojo pipeline** — full training + encode + decode table (all variants, all vocab sizes)
5. **Mojo throughput scaling** — how encode speed and training time scale with vocab size

Capturing: `bash benchmarks/quick_bench.sh > report.md`. Progress messages go to stderr and don't pollute the output.

## Results storage

Raw output files live in `benchmarks/results/`:

```
results/
├── mojo_{LABEL}.json    # Mojo results for one corpus size
├── py_{LABEL}.json      # Python tiktoken results
├── mbpe_{LABEL}.json    # mbpe Python bindings results
└── rs_{LABEL}.json      # Rust tiktoken-rs results
```

Where `{LABEL}` is one of `10KB`, `100KB`, `500KB`, `1MB`, `2MB`, `5MB`.

These are assembled into the final report by `collate.py`:

| Script | What it does |
|--------|-------------|
| `collate.py` | Full report for one corpus: `collate.py [--no-hardware] <mojo.json> <py.json> <rs.json> <mbpe.json>` — executive summary + combined comparison table + native pipeline + scaling. `--no-hardware` skips hardware table for multi-corpus runs. |
| `hardware_info.py` | Standalone hardware info: `hardware_info.py` → hardware markdown table |
| `build_summary.py` | Reads all result files across all corpus sizes → cross-size comparison tables |

## Pre-requisites

### Mojo
- `mojo` CLI available (via `pixi shell` or `pixi run`)
- `bpe/` module (imported via `-I .`)
- `_mbpe.so` built: `mojo build python-binding/mbpe.mojo -I . --emit shared-lib -o python-binding/mbpe/_mbpe.so`

### Python tiktoken
- Python venv at `/tmp/mbpe-bench-venv/` with `tiktoken` installed (auto-setup by `setup_bench_env.sh`)
- Or: activate pixi dev env which includes tiktoken

### mbpe Python bindings
- `_mbpe.so` (same as Mojo build above)
- `PYTHONPATH=python-binding` or run from repo root via `pixi run python`

### Rust tiktoken-rs
- Rust toolchain (auto-installed by `setup_bench_env.sh` via rustup)
- Project in `benchmarks/benchmark_rust/`

### Corpora
- Base corpus `benchmarks/corpus.txt`
- Scaled corpora generated by: `python benchmarks/generate_corpora.py`
- The orchestrator scripts (`run.sh`, `quick_bench.sh`) auto-generate missing corpora

## Quick-start

Build the shared library first (one-time):

```bash
mojo build python-binding/mbpe.mojo -I . --emit shared-lib -o python-binding/mbpe/_mbpe.so
```

### Smoke benchmark (~2 seconds, no file dependencies)

```bash
PYTHONPATH=python-binding python benchmarks/smoke_bench.py
```

Trains all 3 variants on inline corpus (~10 KB), measures encode/decode. No Rust, no tiktoken, no external files needed.

### Quick benchmark (~30 seconds, 1 MB corpus, all 4 implementations)

```bash
bash benchmarks/quick_bench.sh > results.md
```

Runs all 4 implementations on the 1 MB corpus, outputs a complete markdown report (hardware info + results tables) to stdout. Stderr shows progress. Redirect to a file for a ready-to-paste report.

### Full benchmark suite (minutes, 6 corpus sizes, all implementations)

```bash
bash benchmarks/run.sh > results.md
```

Runs all 4 implementations on 6 corpus sizes (10 KB through 5 MB), with 4 vocab sizes each. Outputs hardware info + per-corpus results tables as markdown to stdout.

See environment variables below to skip specific implementations.

### Individual benchmarks

```bash
# Mojo only (uses BPE_CORPUS env var, defaults to benchmarks/corpus.txt)
mojo -I . benchmarks/bm.mojo

# Mojo with explicit corpus
BPE_CORPUS=/path/to/corpus.txt mojo -I . benchmarks/bm.mojo

# Mojo self-contained (inline corpus, no files needed)
mojo -I . benchmarks/benchmark_simple.mojo

# mbpe Python bindings (uses BPE_CORPUS or benchmarks/corpus.txt)
PYTHONPATH=python-binding python benchmarks/benchmark_mbpe.py

# mbpe Python bindings, quick (3 iterations)
PYTHONPATH=python-binding python benchmarks/benchmark_mbpe_quick.py

# Python tiktoken (requires tiktoken in PATH)
python benchmarks/benchmark_tiktoken.py

# Collate existing results
python benchmarks/collate.py results/mojo_1MB.json results/py_1MB.json results/rs_1MB.json results/mbpe_1MB.json

# Build cross-size summary from all results
python benchmarks/build_summary.py
```

## Environment variables

| Variable | Default | Used by |
|----------|---------|---------|
| `BPE_CORPUS` | `benchmarks/corpus.txt` | All individual benchmark scripts — path to corpus file |
| `BPE_NO_RUST` | unset | `run.sh` — set to `1` to skip Rust benchmark |
| `BPE_SKIP_PY` | unset | `run.sh` — set to `1` to skip Python tiktoken benchmark |

## File reference

### Orchestrators

| File | Role |
|------|------|
| `run.sh` | Full suite: all 4 impls × 6 corpus sizes × 4 vocab sizes. Sources `setup_bench_env.sh`, builds `_mbpe.so`, generates corpora, runs all benchmarks, emits markdown report to stdout (progress to stderr). |
| `quick_bench.sh` | Same as `run.sh` but only 1 MB corpus, 3 mbpe iterations. Emits markdown report to stdout. |
| `setup_bench_env.sh` | Installs Rust + Python venv with tiktoken. Sourced by orchestrators. Exports `$VENV_PYTHON`. |

### Mojo benchmarks

| File | Role |
|------|------|
| `bm.mojo` | Entry point — calls `run_all()` from `benchmark.mojo`. |
| `benchmark.mojo` | Core logic: `run_all()` (2 variants × 4 sizes) and `run[PT]()` (single variant). Best-of-20 timing. |
| `benchmark_simple.mojo` | Self-contained benchmark with inline corpus. No file dependencies. |
| `profile_decode.mojo` | Micro-benchmark profiling decode pass-by-pass. |
| `benchmark_approaches.mojo` | Compares 3 BPE encoding strategies (baseline, RankTable, PairCache). |

### Python benchmarks

| File | Role |
|------|------|
| `benchmark_tiktoken.py` | `tiktoken` library — `gpt2` + `cl100k_base`, 20 iterations. |
| `benchmark_mbpe.py` | mbpe Python bindings — `gpt2` / `cl100k` / `o200k`, 20 iterations. |
| `benchmark_mbpe_quick.py` | Same as `benchmark_mbpe.py` but 3 iterations, defaults to `corpus_1MB.txt`. |
| `smoke_bench.py` | Ultra-light (~2 s): inline corpus, all 3 variants, 5 iterations. No external deps. |

### Rust benchmark

| File | Role |
|------|------|
| `benchmark_rust/src/main.rs` | `tiktoken-rs` crate — `p50k_base` + `cl100k_base`, 20 iterations. |
| `benchmark_rust/Cargo.toml` | Rust project manifest. |

### Data processing

| File | Role |
|------|------|
| `hardware_info.py` | Collects CPU model, cores, RAM, OS, tool versions → hardware markdown table |
| `collate.py` | Full report: `collate.py [--no-hardware] <mojo.json> <py.json> <rs.json> <mbpe.json>` — executive summary + combined comparison table (all 4 impls, MB/s + M tok/s) + native pipeline + scaling |
| `build_summary.py` | Reads all `results/*.json` → cross-size summary markdown table |
| `generate_corpora.py` | Generates `corpus_{10KB,100KB,500KB,1MB,2MB,5MB}.txt` from `corpus.txt` |

### Verification / reference

| File | Role |
|------|------|
| `verify_encoding.py` | Python reference BPE encoder — verifies Mojo output byte-for-byte |

### Data files
